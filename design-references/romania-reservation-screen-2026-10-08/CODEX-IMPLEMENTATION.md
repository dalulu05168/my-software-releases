## 数据规则（强制）

- 单页只展示真实 `projectName`、`totalReservedShares`、`remainingShares` 及由其计算的 `remainingPct`。
- `usedShares = totalReservedShares - remainingShares`；`remainingPct = totalReservedShares > 0 ? remainingShares / totalReservedShares * 100 : null`。
- 展示名可由现有后台数据更新，但**大屏上不要出现编辑图标、输入框或修改按钮**。
- 总份额、剩余份额、环形弧长和百分比必须完全一致。右侧环形显示的**剩余比例**而非已用比例；Arc 长度严格由百分比决定。
- 缺少可信份额数据时显示“暂无数据”，绝不把本目录里的演示值当成真实值，也不得随机递减、自动模拟、虚构售罄进度。
- 项目超过总份额/出现负值、并发分配与重复预留等情况应依赖后端校验、事务和权限；前端不可伪造修复。
- 这三个例子只用于 UI 开发：`01: 100,000 / 32,560 = 32.56%`; `02: 50,000 / 12,850 = 25.70%`; `03: 50,000 / 8,900 = 17.80%`，并不是线上配额或实时市场指标。

## 具体验收

1. 提供三张单独的 16:9 大屏，桌面可全屏展示，无多余滚动；1440/1280 与移动端有合理缩放或重排，不裁字、不压线。
2. 主视觉只有项目名称、最大号橙色发光 **剩余份额**、清晰的预留总份额和真实剩余比例；保留大面积留白，避免堆叠卡片。
3. Logo 预留空白替换区，**删除“罗马尼亚金融交易厅”与英文同义大标题**；不要显示任何编辑暗示。
4. 同一项目的数据统一来自服务端可信字段，刷新、切换项目和后台更改后保持一致；无后端数据时不能显示 SVG 示例数字。
5. 橙色 glow 适度（低强度辉光 + 高对比数字），支持 `prefers-reduced-motion`；强制高对比、tabular numbers，不用颜色独自传达数据意义。
6. 变更限于展示层，避免破坏 `project4-render-app` 原有登录/路由/证券/账户/订单/API 功能；构建、类型检查、关键页面与数据格式测试必须通过。
7. 按三个页面分别提供实现截图、数据来源字段映射表、测试结果；创建 PR 供验收，**未经验收不要部署到生产环境**。
